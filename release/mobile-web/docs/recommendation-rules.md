# 演示决策表与规则

本目录对应项目表“效果为真，实现为模拟”的范围。`assets/data/menu.json` 是可替换的 30 道示例菜品；店名和价格均为演示数据，不代表实际营业店铺。组员提供正式素材后在此替换。当前没有组员提供的餐食照片，拍照页通过本地图片预览和可选示例识别结果演示，未伪装成真实图像识别。

`assets/data/decision-table.json` 按“当顿侧重 | 饮食种类”给出固定候选顺序，例如：

```json
{
  "速战速决|米粉面": ["r02", "r08", "r16", "r28", "r03", "r11"],
  "吃点好的|地方菜系": ["r04", "r13", "r18", "r07", "r17", "r29"],
  "default": ["r01", "r02", "r03", "r04", "r05", "r07", "r08", "r09", "r11", "r12", "r21", "r28"]
}
```

流程是确定性的，没有随机推荐：

1. 排除示例配料命中忌口、超过预算、超过辣度、上顿吃过的菜。
2. 读取对应组合、侧重或 default 的预置候选顺序。
3. 按方向、侧重、小目标、上顿偏油偏咸后的清淡搭配、口味偏好排列候选。
4. 优先不同店、不同种类。换一批先排除上一批 id，不放宽忌口与预算。
5. 方向下不足三条时，从其他种类的合规候选补齐，并在页面说明。符合条件的示例不足六条时说明可能重复；完全不可能的自填约束显示调整入口，不能为凑数违反硬约束。

常用选项的组合都有三条结果和两批不重复选择。预算含义为每顿餐费上限 15/25/40 元或不限；示例价格不含配送费、包装费。实际店铺配料与制作方式未接入，页面会提示向商家确认过敏原。

## 规则 prompt（替换真实服务时的行为约定）

> 仅从给定菜品库选择。先排除忌口、上顿同菜、超预算及不可接受的辣度。结合当顿侧重和饮食方向，使用预置决策表选择候选。长期目标作为偏好，上顿偏咸或偏油时优先清淡搭配。展示三个店、菜、价格、标签和具体理由。理由只能引用已保存的事实或本次输入，不编造历史。换一批优先避开上一批，不因候选不足放宽硬约束。无法满足条件时说明具体限制并允许用户修改。

## 演示验收

首次引导选择清淡减脂 → 默认问一问 → 黄焖鸡等三个预置选择 → 文字录入“中午吃了黄焖鸡，有点咸”并核对时间 → 保存到档案 → 再问一顿 → 三个清淡选择，不含黄焖鸡，理由引用“你中午吃了偏咸的黄焖鸡”。
