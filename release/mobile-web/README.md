# 今天吃什么 · 手机 Web v4.0

GitHub v4 当前部署修订为 `4.0.0+deploy.2`，正常启动自动准备 Yunzhong / 1234567890 和 33 餐历史。基础固定版本为 `4.0.0`（v4.0），定版日期为 2026-10-27；预算统一、类别布局和已有记录配图均已并入本版。Git 标签为 `v4.0.0`，独立资产位于 `版本归档/v4.0.0/`。前端为原生 HTML/CSS/JS，后端为 Python / FastAPI。账号、长期偏好、饮食记录、私有照片及画像统计均通过同源 API 保存和读取。v1.0.0、v2.0.0、v3.0.0 固定资产保持独立。

## 本地启动

首次安装：双击项目根目录的 `安装后端依赖.command`，需要 Python 3.11+。随后双击 `启动本地预览.command`。已有新版后端会复用；旧的纯静态 HTTP 服务需先停止。

入口：`http://127.0.0.1:5177/`。正常启动后用 `Yunzhong / 1234567890` 登录，最近饮食和个人档案直接显示已有数据。服务只监听本机，登录或注册后使用，保持启动窗口打开。不能再只用 `python -m http.server` 启动完整应用。

手动启动：

```sh
.venv/bin/python -m backend.run --no-browser
```

## 功能

- 五步长期偏好和三步当顿选择（多选类别、预算、配送时间）分别保存；顶部步骤可点击切换，跨页面返回也可继续本轮未完成问答。
- 推荐读取当前账号的实际餐食和偏好，按多选类别、预算区间、预计配送时间和忌口筛选，按推荐指数降序分页。卡片展示真实菜式参考图、半星一档的健康指数和具体推荐理由；点击“查看推荐依据”进入二级页面，直接展示健康指数、口味匹配、好评参考、月售参考四项评分和修正项。好评参考使用目录好评率参与加权计算。支持上一页、下一页和直接选页码，各页候选不重复。从推荐依据或“选这份”返回时保留原页码、菜品和滚动位置。店铺、价格、月售、配送时间及分数为示例参考。
- 记一顿支持多菜名、最多四张照片、标签、完整用餐时间和备注；从推荐进入会带入菜名、标签和参考图片，可继续编辑后保存；年月日筛选、查看详情和确认删除。
- 照片上传到后端私有目录，缩至最长边 1600px 并清除原 EXIF。上传后自动识别并填入可编辑的菜名和标签，保留识别期间的手动修改，保存餐食后才参与统计。
- 已配置的视觉服务使用 OpenAI Python SDK 的 Chat Completions 图片输入与流式输出。模型地址、密钥、模型名以及深度思考开关均在后端环境中配置。缺少配置、超时或识别失败时仍可手动记录。
- 我的展示累计菜品种类、记录餐数、记录天数、常吃食物 Top 3 和六维口味标签比例；由后端确认记录计算。
- 设置提供昵称、展示 ID、输入开关、长期偏好编辑和退出登录。内部账号 ID 与展示 ID 独立。
- 本机旧数据保留；在同一浏览器、同一 `127.0.0.1:5173` 来源的设置页手动导入记录。默认排除旧版示例，也可主动勾选包含示例；重复导入按原标识去重并校验目标账号。
- 语音入口使用设备键盘听写，网页不录音。

## 数据和配置

本地默认使用 `.data/meals.sqlite3` 和 `.data/photos/`，均不在静态目录中；登录后的数据按用户隔离。服务端会话以 HttpOnly Cookie 保存，数据库仅保存令牌摘要。密码使用 scrypt 加盐散列。

复制 `.env.example` 为 `.env` 配置环境；`.env`、数据库、照片和虚拟环境均被 Git 与容器构建排除。不要把真实密钥写入前端、说明文档或版本归档。部署可切换 PostgreSQL，说明见 [后端运行与部署](docs/backend.md)。

## 固定版本

v4.0.0 的独立副本、ZIP 和 SHA-256 校验清单位于项目根目录的 `版本归档/v4.0.0/`。合并前的 v4.0.0 固定包保存于 `版本归档/历史/v4.0.0_合并前_20261027/`，对应备份标签 `v4.0.0-before-merge-20261027`；先前的 v4.0.1 包与标签作为历史快照保留。归档包含前后端源码、数据库迁移、依赖锁定文件、启动脚本和运行说明；模型密钥、账号数据库、私人照片和虚拟环境继续保留在本机，不进入固定资产。

本 GitHub 分支在基础源码上增加正常启动初始化，当前交付清单与原固定清单分开保存，见仓库根目录 README。Docker 默认 SQLite，PostgreSQL 配置见 `compose.postgres.yaml`。Docker/PostgreSQL 部署文件已提供，Docker 容器和公网环境尚未实测。后续修改在工作目录继续进行，并使用新的版本号和归档目录；v1.0.0、v2.0.0 与 v3.0.0 的固定资产和标签保持不变。
